Luồng hoạt động Backend — Azure RAG PoC

Sơ đồ đọc theo source hiện có: API nhận yêu cầu, các service gọi SharePoint / Microsoft Graph / Azure AI, rồi lưu hoặc truy vấn dữ liệu. Những bước thuộc Logic App hay Azure không được suy diễn thành code backend.

Cách đọc: “Backend làm” nghĩa là có logic tương ứng trong repository. “Dịch vụ ngoài” nghĩa là backend gọi API/endpoint nhưng phần xử lý bên trong không nằm trong source này. Đây là PoC/base; các nhánh có thể độc lập, không phải mọi request đều chạy qua tất cả pipeline.

3. ACL, tìm kiếm và ReRank

ACL trong retrieval

AzureSearchService.build_acl_filter dựng bộ lọc OData dựa trên allowed_user_ids và allowed_group_ids. Luồng chat truyền user object ID và group IDs vào retrieval; kết quả tìm kiếm bị giới hạn theo filter này.

AzureChunkRepository chỉ patch sensitivity. Không thấy backend writer điền allowed_user_ids/allowed_group_ids khi tạo hoặc cập nhật chunk.

Kết luận từ source: backend đọc/dùng các ACL fields để lọc; source hiện có không chứng minh ai ghi các field đó. Khả năng quyền được đồng bộ ở pipeline Azure/SharePoint là giả thuyết hợp lý, nhưng cần xem Logic App/indexer hoặc cấu hình Azure mới kết luận được.

Thứ tự retrieval và ReRank

  1. Phân tích/rewrite câu hỏi thành query (Azure OpenAI).
  2. Tạo query embedding.
  3. Azure AI Search chạy hybrid text + vector, kèm ACL/workspace/document type filter tùy endpoint.
  4. Luồng RAG chính lấy parent_id của kết quả đầu, rồi truy vấn thêm các chunk thuộc cùng tài liệu.
  5. Context chuyển sang bước trả lời/review bằng LLM.
Không thấy ReRank riêng trong source đã rà: không có service reranker, cross-encoder, hay bước gọi semantic-ranker riêng sau retrieval. Thứ tự đang dùng là kết quả Azure Search (score hybrid). Có semantic configuration ở dịch vụ Azure hay không phải kiểm tra cấu hình/index ngoài repo.

4. Chat RAG và nguồn dữ liệu pháp lý

Chat tài liệu doanh nghiệp

Chat RouterNhận câu hỏi và identity/group context.
→
AzureSearchService.retrieveHybrid search + ACL filter, query embedding, chọn parent document.
→
Context + promptCác chunk được đưa vào pipeline trả lời (RAG) cùng model/prompt cấu hình.
→
ResponseTrả nội dung và thông tin nguồn/citation theo route.

CompanyPolicyRetrievalService

Nhận các company-rule checks do analyzer tạo; xử lý từng check có giới hạn đồng thời, gọi AzureSearchService.retrieve_contract_policy qua thread. Retrieval lọc document_type = CONTRACT_POLICY, dùng hybrid search, rồi gom/deduplicate context.

Không dùng ACL filter ở nhánh retrieval này theo code đang đọc.

LegalRetrievalService (contract advanced)

Tìm trong legal corpus cục bộ qua DuckDB FTS/BM25: query ghép từ các metadata seeds được cho phép; lấy tối đa 1 legal document cho mỗi check; tải văn bản/metadata từ bảng legal_documents. Các check chạy song song có semaphore.

Đây là nhánh luật trong ContractAdvancedService, độc lập Azure AI Search.

LegalChatRetrievalService + LegalChatService

Legal Q&A phân tích câu hỏi thành metadata seeds, truy vấn DuckDB FTS (top-k 4), rồi LLM trả lời từ contract text và legal context. Không có context thì trả lời theo nhánh “không có bằng chứng”.

LegalContractAnalysisService (SSE)

Nhận contract text đã extract; analyzer LLM sinh legal checks (tối đa 8, seed bị giới hạn); mỗi check truy vấn LegalChatRetrievalService (top-k 4), reviewer LLM đánh giá COMPLIANT/RISK/UNCLEAR và phát từng kết quả qua SSE, kết thúc bằng completed.

ContractAdvancedService — ghép 2 nhánh review

Extract hợp đồng bằng Azure Document Intelligence prebuilt-layout; LLM phân tích thành company-rule checks và legal checks; chạy pipeline company-policy (Azure Search) và legal retrieval (DuckDB) đồng thời; reviewer LLM tạo kết quả riêng cho từng nhánh.

Extraction khác nhau theo route: có luồng dùng Azure Document Intelligence, luồng khác dùng Docling.

5. Theo dõi dự án — Project Tracking

Đọc dữ liệu dự án từ Excel trên SharePoint

  1. AzureProjectTrackingService.get_projects tìm site/library theo setting, liệt kê file .xlsx.
  2. Đọc metadata list item: Code_project, Data_type, Enable_AI; bỏ qua file không có project code hoặc bị tắt AI.
  3. ProjectTrackingReaderService gọi Graph workbook API đọc worksheets và usedRange.
  4. Chuyển hàng đầu thành header; parse các sheet Project, Tasks, Members, Risks và các sheet khác.

Routes gồm danh sách/detail project và các route sync theo toàn bộ hoặc theo project code.

Graph ingestion xử lý chunk đã được index sẵn. Nó không phải quy trình tạo chunk hoặc ghi tài liệu ban đầu vào Azure Search.

8. Các nhánh backend khác cần biết

Recruitment / CV

CV được trích xuất (có nhánh Docling), phân tích ứng viên; ingestion CV tạo embedding cho nội dung rồi lưu CV cùng vector dạng JSON trong campaign DB. Đây là luồng khác với index chunk tài liệu RAG.

Profile và transcript

Theo thông tin tiến độ bạn đã cung cấp: Azure xử lý auth/streaming/transcript; backend đối chiếu Azure profile với User DB và nhận transcript để review. Đây là ranh giới vận hành do bạn mô tả, cần đọc đúng router/service tương ứng nếu muốn map từng endpoint.

Delta / cấu hình SharePoint

/documents/delta/check gọi Microsoft Graph/DeltaService kiểm tra thay đổi; các routes sites/lists/config/upload-options hỗ trợ chọn nguồn và cấu hình. Đây không đồng nghĩa với chunking/indexing.

Contract basic / extraction

PoC có nhiều đường xử lý hợp đồng. Một số dùng Docling để extract, các advanced/legal path có Azure Document Intelligence hoặc nhận text đã extract. Luồng cụ thể phụ thuộc endpoint; không nên gộp thành một extractor duy nhất.

9. Những kết luận quan trọng từ lần rà source này

Câu hỏiĐiều source backend xác nhận
Ai gọi Document Intelligence?Có backend utility/service gọi Document Intelligence trong các luồng extract/review hợp đồng. Riêng ingest RAG qua Logic App: backend chỉ trigger URL và nhận callback; không thấy bước Document Intelligence bên trong backend orchestration.
Ai chunk, embedding và ghi tài liệu vào index?Không tìm thấy pipeline backend đầy đủ cho ingest chunk mới vào Azure Search. Backend đọc chunk đã có, truy vấn vector, và patch sensitivity. Tạo index/chunk embeddings/full document write thuộc pipeline ngoài hoặc phần chưa có trong source đang rà.
Ai điền ACL vào index?Backend dùng allowed_user_ids/allowed_group_ids làm query filter, nhưng không thấy writer cho chúng. Chưa đủ bằng chứng trong repo để khẳng định Logic App hay SharePoint sync ACL.
Có ReRank không?Không thấy reranker riêng trong backend; hiện retrieval nhận thứ tự/score từ hybrid Azure Search rồi tiếp tục xử lý context.
Legal retrieval nằm đâu?Company policy tìm trên Azure AI Search; legal corpus tìm bằng DuckDB FTS/BM25 trong nhiều service legal/contract. Có nhiều luồng phân tích và chat riêng.
Project tracking và executive data?Đều là pipeline riêng đọc Excel qua Graph, phân tích bằng LLM, lưu raw/dashboard DB và có detection-based chat; worker tự động đang bị comment tại startup.

Tài liệu học tập dựng từ source backend hiện có trong repository. Các kết luận “không thấy” chỉ mô tả phần code đã rà; Logic App, Azure Search indexer/schema/skillset và quyền cấu hình trên Azure cần được đối chiếu ở môi trường Azure để xác nhận bên ngoài repository.
